arcsum — live agentic meeting summarizer

A 1B model reads a Traditional-Chinese transcript in ~2,500-token chunks, curating a two-slot external memory (ARC + POINTS) with ADD / DROP / ARC / NOP edit lines. No conversation history crosses steps — the memory is the only thing carried forward. A final SYNTHESIZE call turns it into prose. Everything runs in your browser.

What you are watching

The middle panel is the model's raw output — it emits only edit lines, never prose, until the very end. The right panel is the harness's memory after applying them deterministically, with the token caps enforced and malformed or unsafe ops refused.

The design bet is what that memory buys: a later chunk can overturn an earlier conclusion. Map-reduce cannot — it summarises each window independently, so a decision reversed at minute 90 never reaches the summary of minute 10.

The losses concentrate in long meetings, where the model fixates — the known open weakness. Full numbers and caveats on the model card.

About this demo

  • The model (~656 MB, Q4_K_M) downloads once and is cached by your browser. Later runs start immediately.
  • Q4_K_M is not the evaluated artifact — every gate number above was measured on Q8_0. Nothing you see here is an eval result.
  • The harness (arcsum.js) is a port of the Python package, differential-tested byte-for-byte against it on prompts, chunking, op parsing, memory eviction and prose cleanup. The mechanism is real, not re-enacted.
  • Examples are real held-out meetings from the evaluation set, deliberately short ones — in-browser CPU inference is slow, and the model's weakness is long meetings.
  • Previously this Space demoed CURSOR, the prior project's protocol (ADD/UPD/DEL/CMP/NOP over a single NOTES state). That is a different, superseded architecture; the URL slug still says cursor-wasm-demo for continuity.
